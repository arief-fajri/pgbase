# Backup, Restore, and Observability

> Audience: Operator · Status: stable · Last verified: v0.5.2 (`923e860`)

## 1. Backup formats

A backup is a `.zip` of `pb_data` (storage files + full DB dump) under
`pb_data/backups` (or S3). Format is `Backups.Format`:

| Format | Contents | Restore path |
|---|---|---|
| `pg` (default) | Native `pg_dump -Fc --no-owner --no-privileges` archive (`pgdata.dump`): **entire** DB — schema, record tables, `_params`, `_migrations`, `_superusers`, `_logs`, partitioned `_audits`/`_audit_reads`. Exact-replica DR snapshot | `pg_restore --clean --if-exists --no-owner --no-privileges` |
| `sqlite` (legacy, opt-in) | Portable v0.23-format `data.db`: records + schema + settings only (no request logs). Single MVCC transaction; pins xmin horizon on huge DBs, holds one data-pool conn | Normalized import |

Restore auto-detects (`pgdata.dump` → native, `data.db` → legacy).
Implementation: `core/base_backup.go:28-42,103-116`, `core/backup_pg_export.go:142-144`,
`core/backup_pg_import.go:56-84`, `core/backup_sqlite_*.go`.

Requirements (native path): `pg_dump`/`pg_restore` on `PATH`, client major `>=`
server major; overrides `PB_PG_DUMP_BIN`/`PB_PG_RESTORE_BIN` (must be regular
executable, validated in `core/backup_pg_export.go:83-110`); password via
`PGPASSWORD` env (`core/backup_pg_export.go:30-79`). Release image ships v16 client.

```bash
./pgbase backup                       # configured format, autogenerated name
./pgbase backup snap.zip
./pgbase backup snap.zip --format sqlite
./pgbase restore snap.zip             # OFFLINE, no restart (restart after to load data)
```

Also via dashboard, `/api/backups` (superuser-only), autobackup cron
(`Backups.Cron`, job `__pbAutoBackup__` in `core/base_backup.go:447`).
Creation bounded ~10 min; restore ~10 min; decompression capped by
`PB_BACKUP_MAX_EXTRACT_BYTES` (default 8 GiB, `tools/archive/extract.go:16-39`,
zip-slip + `LimitReader` guarded; S3 downloads capped too).

> **Trust boundary:** restore replays the archive (`--clean`), i.e. executes
> arbitrary SQL from the dump. A tampered archive = DB takeover. Guard the
> bucket/filesystem like DB credentials (`../PRODUCTION.md` §7).
> PITR/WAL (`pgBackRest`/`WAL-G`), incremental backups, S3 auto-offload, and
> restore drills are `roadmap-open` (Theme F).

## 2. Logs vs audits (what to watch)

| Stream | Table / API | Notes |
|---|---|---|
| Request logs | `_logs` on **aux** DB (`core/log_model.go:9`), `GET /api/logs` + `/logs/stats` (`apis/logs.go:13,39`) | Plain table; retention `__pbLogsCleanup__ 0 */6 * * *` (`core/base.go:1544`); bulk DELETE bloat; RANGE-partition is `roadmap-open` (PERF-I04) |
| Data audits | `_audits` (+ `_audit_reads` metadata-only), `GET /api/audits` (+ `/{id}`, `/reads`) superuser-only (`apis/audits.go:12-34`) | Month-RANGE partitioned + DEFAULT (`migrations/1787237001_audits_init.go:25-67`); next-2-months pre-created (`core/audit_hooks.go:455-475`); retention jobs `__pbAuditsPartition/Cleanup__ 0 0 * * *`; changes/snapshot redacted |
| Dashboard | `#/logs` (chart/list/preview) + `#/audits` (Data-changes / Read-access tabs) + `#/settings/audit` | v0.2.0 audit UI |

## 3. Prometheus `/metrics` (opt-in, separate listener)

```bash
PB_METRICS_ADDR=127.0.0.1:9090 ./pgbase serve --http=0.0.0.0:8090
curl http://127.0.0.1:9090/metrics
```

- `PB_METRICS_ADDR` empty/unset (default) = disabled (no listener, no middleware overhead).
- `PB_METRICS_EXPOSE=true/1` required to bind a **non-loopback** address
  (e.g. `0.0.0.0:9090` in a container behind a NetworkPolicy); loopback never needs it.
  `/metrics` is **unauthenticated** — loopback or protected internal only
  (`apis/metrics.go:34-89`, `apis/serve.go:90-105`).

| Metric | Type | Labels | Meaning |
|---|---|---|---|
| `pgbase_http_request_duration_seconds` | histogram | `method`, `route`, `status` | `route` = matched template (low cardinality) |
| `pgbase_db_open_connections`, `pgbase_db_in_use_connections`, `pgbase_db_idle_connections`, `pgbase_db_max_open_connections` | gauge | `db=data\|aux` | live `sql.DB.Stats()` per pool |
| `pgbase_db_wait_count_total` | counter | `db` | pool saturation signal |
| `pgbase_db_wait_duration_seconds_total` | counter | `db` | time blocked on pool |
| `pgbase_realtime_connected_clients` | gauge | — | SSE clients |
| `pgbase_realtime_dropped_messages` | gauge | — | slow-consumer drops (queue 32) |

Plus Go runtime + process collectors. Alert first on
`rate(pgbase_db_wait_count_total[5m]) > 0` or p99 latency rise
(`deploy/prometheus.rules.yml`, `../PRODUCTION.md` §8, `../DEV.md` §3d).
Scrape examples (same-host, compose loopback publish, bundled
`deploy/docker-compose.monitoring.yml`): `../PRODUCTION.md` §8.1.
Per-collection latency, hit/miss, outbox-lag, backup-size metrics + shipped
Grafana dashboards + OTel tracing are `roadmap-open` (Theme D).
