## Context

The scheduled `security-scan` workflow went red on two jobs, both reproduced
locally:

1. **govulncheck:** 12 reachable stdlib vulns (`net/http`,
   `mime/multipart`, `crypto/tls`, `html/template`), all fixed in go1.26.9,
   plus `golang.org/x/net@v0.58.0` (fixed in v0.60.0). Root cause: `go.mod`
   pins `toolchain go1.25.14`, which forces toolchain-switching back to the
   vulnerable toolchain even though every CI workflow already runs Go
   `>=1.26.5` — govulncheck analyzes the pinned toolchain's stdlib, so CI
   fails deterministically.
2. **npm-audit (ui):** 1 high — `source-map-js` GHSA-68fv-2mgg-jv7q, fix
   available. The docs leg is clean (0 vulns); only the ui leg is red.

## Options considered

| Option | Trade-offs |
|---|---|
| 1. Toolchain-only bump + x/net bump (recommended) | `toolchain go1.25.14` → latest go1.26.x; `go` directive stays `1.25.0` (legal: toolchain ≥ go directive). Minimal blast radius: no language-version change, CI runners already ≥1.26.5 so no download there. Risk: x/net v0.60.0 may need a newer `go` directive — caught by `go mod tidy` + full suite |
| 2. Full `go` directive bump to 1.26 | Larger blast radius (language semantics, all CI/release Go pins, docs) for no additional security benefit beyond option 1 |
| 3. npm-audit only, defer Go | Leaves govulncheck red; DRR-0004 criterion 6 (security posture current) stays violated |

## Recommendation

Option 1 + `npm --prefix ui audit fix` (lockfile only; `ui/src` untouched so
`ui/dist` needs no rebuild per AGENTS.md, but `npm run build` is re-verified).
Small docs touch if "Go 1.25+" claims become inaccurate
(`contributing.md`, `releasing.md` point at `developing.md` as truth).

## Risks / reversibility

- **x/net behavior change:** exercised by the full DB-backed suite + race
  subset; fallback is an intermediate x/net pin recorded here.
- **Toolchain download:** local/CI with pinned or cached toolchains
  transparently use them; `GOTOOLCHAIN=auto` is the default.
- **Reversibility:** `go.mod`/`go.sum` + `ui/package-lock.json` revert;
  no schema, route, or contract change.

## Outcome

Applied 2026-10-12:

- `go.mod`: `toolchain go1.25.14` → `go1.26.9` (latest 1.26, verified via
  go.dev release feed); `go get` pulled `golang.org/x/net@v0.60.0` and, as
  its precondition, raised the `go` directive `1.25.0` → `1.26.0` plus
  companion x/ bumps (crypto v0.57.0, mod v0.41.0, sync v0.23.0, sys v0.48.0,
  text v0.42.0). `go mod tidy` clean.
- `ui/package-lock.json`: `source-map-js` 1.2.1 → 1.2.2 (the GHSA fix) +
  npm-canonical indent normalization on the root `name` line (kept: it is
  what the toolchain generates, so reverting would only churn again).
  `ui/dist` byte-identical after rebuild — the fix is build-neutral.
- Docs: `developing.md` / `contributing.md` / `releasing.md` prereqs
  `Go 1.25+` → `Go 1.26+` in the same change (no drift).
- Verification: `govulncheck ./...` → 0 reachable (1 require-only advisory
  remains informational, exit 0 — the workflow's documented semantic);
  `npm audit` ui + docs → 0; `go build ./...` OK; full
  `go test ./... -p 4` green; `apis -race` green; `golangci-lint` 0 issues
  (local binary rebuilt via `go install @v2.6.2` — the old binary was built
  with go1.25 and refuses a 1.26 target; CI builds it from the runner's Go
  so no workflow change needed); `make docs-check` clean.
- Learned: recorded in `evidence/learnings.md` (2026-10-12 toolchain entry).
