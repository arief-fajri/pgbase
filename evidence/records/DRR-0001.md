## Decision

- **Authority level:** B
- **Guard rails / invariants implicated:** G-DB-05 (credentials/config source — upheld, unchanged), G-AI-02/03 (this process); failure-modes §3 release-blocking rule (class A+B+D ⇒ non-code layers must land in the same PR). No new guardrail — this decision *removes* a mechanism rather than adds one.
- **Requester:** agent (opencode)
- **Date opened:** 2026-09-25
- **Status:** applied

## Context

`realtimeOutboxListenerConfig` (`core/realtime_outbox.go`) assembles the pgx `LISTEN`
connection config: user/dbname from the live connection; host/port intended to follow
the live connection via `SELECT COALESCE(inet_server_addr(), '') AS host, inet_server_port() AS port`.

That query always fails: `COALESCE` coerces the `''` literal to `inet` at parse analysis
(`invalid input syntax for type inet: ""`). The `err == nil` guard swallows the error, so
the host/port override never executed — dead code, silent failure (classification A + B + D, W-11).

Fixing the cast would make the query succeed, but the value it returns is the server-side
view of the connection. Where the client reaches PostgreSQL through NAT/port mapping
(Docker Desktop macOS/Windows, managed PG, pgbouncer), the server-side address (container
IP, in-container port) is not dialable from the client process. The listener lives in the
same process as the client, so a server-side address can never be a universally correct
dial target — this would redden `apis/realtime_outbox_listener_test.go` on macOS and make
listener behavior environment-dependent.

Precedent: the backup path already made this decision. `pgConnInfo()` (`core/backup_pg_export.go`)
resolves host/port/user/password/sslmode from `ResolveDBConfig` (env) and reads only
dbname/schema from the live connection, with an explicit comment that a custom `DBConnect`
may override the database name. The only custom-`DBConnect` consumer in-tree (test harness,
`tests/app.go`) already syncs `PB_POSTGRES_HOST/PORT` from the test connection so the
listener resolves the same target — stored-config host/port is the de facto, depended-upon
behavior.

## Options considered

| Option | Trade-offs |
|---|---|
| 1. Drop the host/port override; listener dials stored-config host/port (align with `pgConnInfo`). | Zero behavior change (branch is dead). Makes de facto behavior deliberate, documented, and test-locked. Custom `DBConnect` stays honored for user/dbname. Custom host/port not honored — a documented limitation instead of a promise the code cannot keep. |
| 2. Fix the cast: `COALESCE(host(inet_server_addr()), '')` + `COALESCE(inet_server_port(), 0)`. | Honors the original comment's intent, but the derived address is the server-side view: unroutable exactly in NAT/port-mapped topologies; listener behavior becomes environment-dependent; e2e listener test goes red on macOS/Windows dev. Trades "silently ignored custom host" for "listener that cannot connect". |
| 3. Leave as-is + W-11 row only. | No code churn, but keeps an always-failing query, a comment promising behavior the code does not have, and a swallowed error — the porosity guardrails exist to close. No payoff given option 1 is small and behavior-preserving. |
| 4. Change the `DBConnectFunc` contract so closures report the resolved config (captured at init). | Architecturally correct way to honor custom host/port, but a Level B change to the public Go embedding API with no in-tree consumer needing it (harness syncs env). Deferred unless an embedder asks. |

## Recommendation

**Option 1** — remove the dead host/port override in `realtimeOutboxListenerConfig`, keep
the user/dbname override, align the doc comment with the `pgConnInfo` precedent. Record as
W-11 (class A+B+D, fixed-by-removal) in failure-modes.md in the same PR; lock the contract
with a regression test asserting `cfg.Host/Port == app.dbConfig.Host/Port`.

## Risks / reversibility

- **Blast radius:** none observable — the removed branch never executed; the listener DSN is byte-identical before/after. No `api-contract.md` entry required (no caller-visible behavior change; hard rule 2 satisfied by absence of change).
- **Reversibility:** fully reversible (single-file revert).
- **Risk of future "fix":** a future session may re-add the override thinking it is a bug; mitigated by this DRR, the W-11 row, and the regression test asserting stored-config host/port.
- **Evidence of success:** `go test ./core/... ./apis/...` green including `TestRealtimeOutboxListenerRebroadcasts` (listener e2e unchanged) and the new assertion; `golangci-lint` clean.

## Outcome

Applied 2026-09-25 in the same PR as the W-11 row, the learnings entry, and the code
change (`core/realtime_outbox.go` override branch removed; doc comment aligned with
`pgConnInfo`). Verified locally (macOS, PostgreSQL 16 via `tests/docker-compose.test.yml`):

- `go test ./... -count=1 -p 4 -timeout=1200s` — full suite green, zero FAIL.
- `go test ./core/ ./apis/ -race -count=1` — green.
- `TestRealtimeOutboxListenerConfigIgnoresTestEnv` passes with the new W-11 assertions
  (`cfg.Host/Port == app.dbConfig.Host/Port`); `TestRealtimeOutboxListenerRebroadcasts`
  (listener e2e) unchanged and green — zero behavior change confirmed.
- `golangci-lint run -c ./golangci.yml ./...` — 0 issues; `gofmt` clean; `make docs-check` clean.

Lesson recorded in `evidence/learnings.md`: a dial target cannot be derived from the
server-side view of the connection; stored config is the only universal source for
host/port, live-connection introspection only for identity fields the server owns.
