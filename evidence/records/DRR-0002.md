## Decision

- **Authority level:** B
- **Guard rails / invariants implicated:** hard rule 2 + I6/I7 (new public route = caller-visible change: contract entry, golden update, regression test), I8 (deterministic 200/503 semantics), G-SEC-06 (a public unauthenticated endpoint — same exposure class as `/api/health`; the response leaks no database detail: static messages only)
- **Requester:** agent (opencode)
- **Date opened:** 2026-09-25
- **Status:** applied

## Context

Phase 0 roadmap item "Readiness distinct from liveness": `/api/health` is liveness-only and never touches the database, but two production artifacts used it as a readiness signal — the `docker-compose.prod.yml` container healthcheck and the `deploy/quickstart.sh` boot wait loop — so a container counted as "healthy" during a full database outage, and the installer's wait loop could pass before the app could actually serve.

## Options considered

| Option | Trade-offs |
|---|---|
| 1. New public route `GET /api/ready` (200/503) | Additive — no compat risk; the probe exercises the real serving pool and the core schema; requires contract/golden/docs updates. |
| 2. Make `/api/health` check the database | No new route, but breaks liveness semantics (a load balancer would kill a healthy process during a DB outage) and silently changes the PocketBase-compat surface. |
| 3. Readiness on the metrics listener | No public-surface change, but `/metrics` is opt-in and loopback-only — LB/Kubernetes probes cannot reach it. |

## Recommendation

Option 1, with these specifics (confirmed by maintainer 2026-09-25):

- one bounded probe query through the normal data pool —
  `SELECT (SELECT count(*) FROM "_collections")` (proves pool acquire + server answer + core
  schema readable), bounded by a 5 s `context.WithTimeout` over the request context;
- 503 body is a **static** ApiError message (`"API is not ready."`) — the raw driver error is
  logged server-side only, never in the response body (driver errors can contain host/user
  details);
- `/api/health` unchanged (liveness-only);
- both deployment artifacts switch to `/api/ready`: `docker-compose.prod.yml` healthcheck and
  the `deploy/quickstart.sh` wait loop.

## Risks / reversibility

- **Blast radius:** one new public unauthenticated route (200/503, behind the standard rate-limit middleware; no DB detail in any response); contract §9 added (old §9 renumbered to §10); golden +1 route; both deployment artifacts switch probe target.
- **Reversibility:** fully reversible — revert the file set; the route is additive, no existing caller breaks.
- **Rollback:** revert the commit; no migrations or data involved.
- **Evidence of success:** `apis/ready_test.go` (guest 200 / superuser 200 without health's superuser extras / data pool closed → 503 with no raw error in the body / health stays 200 with the pool closed); `api_surface.golden` diff is exactly `+GET /api/ready`; full suite + lint + docs build green.
