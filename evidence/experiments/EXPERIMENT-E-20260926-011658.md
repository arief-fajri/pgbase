## Scenario

Same as the first run (2026-09-12): a native pg backup must round-trip —
after the database schema is destroyed, the archive must restore a valid
schema, data, and superuser auth state. This re-run exercises the NEW restore
gate (`core/backup_pg_verify.go`): pre-restore TOC validation, stderr
classification with a benign allowlist, and archive-derived completeness +
semantic verification instead of the old `count(_collections) >= 1` gate.

## Procedure

`bash evidence/experiments/EXPERIMENT-E.sh`

1. Fresh DB `pgbase_exp_e`; schema pre-provisioned; `serve` starts; ready OK.
2. `superuser upsert admin@example.com testpass123`.
3. Insert probe row into `_params` (`id='exp_e_probe', value='42'`).
4. Record pre-backup counts (`_collections`, `_params`, `_superusers`,
   password-hash length).
5. Stop the app; `pgbase backup exp-e.zip --format pg`.
6. Destroy the schema: `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`.
7. `pgbase restore exp-e.zip`; record post-restore counts + exit code.

## Results

- backup: rc=**0**, `backups/exp-e.zip` **created**
- restore: rc=**0** — the hardened gate passed a full valid restore, including
  tolerating the observed benign pg_restore noise of this environment
  (`unrecognized configuration parameter "transaction_timeout"` from the
  pg_dump 18.3 client against the 16.15 server)
- `_collections`: 6 → **6**; `_params`: 2 → **2**; probe row: **1**;
  `_superusers`: 1 → **1**; password-hash length: 60 → **60**

## Verdict

**PASS** (L2). The hardened gate neither false-alarms on a valid restore nor
weakens the old gate — the failure paths are covered by the regression tests
(`core/backup_pg_verify_test.go`, `core/backup_pg_scenario_test.go`:
corrupt-archive rejection before the destructive restore, missing TOC table,
missing TOC index, missing settings row, missing superuser password).
