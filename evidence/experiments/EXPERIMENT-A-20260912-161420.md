## Scenario

With PostgreSQL down, HTTP requests must fail with bounded errors (no
infinite hangs) and the app must stay alive; once the database returns,
requests must recover deterministically. The outage is a real container
stop/start of the shared test Postgres.

## Procedure

`bash evidence/experiments/EXPERIMENT-A.sh`

1. Fresh DB `pgbase_exp_a`; schema pre-provisioned; `serve --http=127.0.0.1:8099`;
   probe a DB-backed guest route (`GET /api/collections/users/records` → 200).
2. `docker compose ... stop postgres-test` (real outage).
3. 3 probes while down; measure boundedness, then check the app process.
4. `docker compose ... start postgres-test`; wait for the DB-backed route to
   return 200 again.

## Results

- ready: **yes**

  no hang — curl never waited its 8 s cap)
- app alive after outage: **yes** (probe wall ~1 s)
- recovery: DB-backed route **200** after container start
