## Scenario

A native pg backup must round-trip: after the database is destroyed, the
archive must restore a valid schema, data, and superuser auth state
(collections table present, `_params` probe row present, superuser row with a
non-empty password hash). Full auth E2E is covered by the Go backup round-trip
test.

## Procedure

`bash evidence/experiments/EXPERIMENT-E.sh`

1. Fresh DB `pgbase_exp_e`; schema pre-provisioned; `serve` starts; health OK.
2. `superuser upsert admin@example.com testpass123`.
3. Insert probe row into `_params` (`id='exp_e_probe', value='42'`).
4. Record pre-backup counts (`_collections`, `_params`, `_superusers`,
   password-hash length).
5. Stop the app; `pgbase backup exp-e.zip --format pg`.
6. Destroy the schema: `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`.
7. `pgbase restore exp-e.zip`; record post-restore counts.

## Results

- backup: rc=**0**, `backups/exp-e.zip` **created**
- restore: rc=**0**
- `_collections`: 6 → **6**; `_params`: 2 → **2**; probe row: **1**;
